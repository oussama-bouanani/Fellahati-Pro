## اختبارات الخصم

- القراءة العامة أو بدون تسجيل: مرفوضة بالرفض الافتراضي وشرط المالك.
- قراءة أو كتابة سجل مستخدم آخر: مرفوضة بمقارنة UID في المسار مع Firebase Auth.
- تجاوز التحقق عبر update: مرفوض؛ الإنشاء والتحديث يستعملان `isValidRecord` نفسه.
- تغيير المالك أو حقن `uid`: مرفوض بالمخطط الصارم وشرط المسار.
- تغيير معرف السجل: مرفوض لأن `data.id` يجب أن يساوي معرف الوثيقة.
- حقن حقل غير معروف: مرفوض بواسطة `hasOnly`.
- حذف حقل مطلوب: مرفوض بواسطة `hasAll` والمدقق الكامل.
- نصوص أو صور ضخمة: مرفوضة بحدود طول لكل حقل نصي والصورة.
- إحداثيات خارج النطاق أو بنوع خاطئ: مرفوضة.
- نوع شجر خارج الكتالوج المحدد، قيمة غير صحيحة أو عدد سالب/ضخم: مرفوض. الكتالوج يسمح بـ36 نوعاً معروفاً مع خيار «أشجار أخرى».
- أرقام سالبة أو ضخمة في المساحة والكمية والأسعار: مرفوضة.
- تصعيد الصلاحيات أو دور admin: لا توجد أدوار يحددها العميل، وأي حقل زائد مرفوض.
- تسريب محتوى مختلط: لا توجد قراءة مشتركة؛ كل البيانات خاصة بالمالك.
- استغلال عداد أو انتقال حالة أو مسار تخزين: غير منطبق على نموذج السجلات الحالي.
- سجل فرعي بدون وثيقة أب: لا يمنح صلاحيات إضافية؛ العزل مبني مباشرة على UID المصادق عليه في المسار.
- عدم تطابق الاستعلام: التطبيق يقرأ فقط مجموعة سجلات المستخدم نفسه، وهو الاستعلام المسموح.

تم تجميع القواعد بنجاح بواسطة Firebase CLI `--dry-run`. تبقى اختبارات Emulator غير منفذة على هذا الجهاز لعدم توفر Java.
